# DBPulse — 변하지 않는 프로젝트 헌장

## 제품의 목적
외부 사용자가 자신이 관리하는 데이터베이스를 **안전하게 연결**해 장애 감지·복구, 실시간/누적 성능 분석, 저성능 쿼리 진단·튜닝 추천을 통합적으로 사용할 수 있는 **실제 운영 서비스**를 개발한다. 교육용 실습, 단순 모니터링 대시보드, 부하 테스트 도구 자체가 최종 산출물이 아니다.

## 변경하지 않을 3대 제품 기능

1. **장애 감지·원인 진단·안전한 자동복구**: DB 접속 장애, Blocking, Deadlock, 비정상 지연 등을 탐지하고 이력화. 검증된 저위험 조치는 정책에 따라 자동 복구. 쿼리 강제 종료·DB 재시작·인덱스 변경 등 위험한 작업은 기본적으로 승인 필요.
2. **쿼리 및 트랜잭션 성능 분석**: 실행 시간, CPU, Reads, Lock/Wait, 실행계획, Query Store의 실행 이력을 연계하여 이상 징후 및 변경 전후 성능을 분석. 수집 시점의 DMV 스냅샷과 완료된 쿼리 누적 통계는 반드시 구분.
3. **쿼리 튜닝 추천**: 저성능 SQL 식별·이력 관리·실행계획 진단, 인덱스/쿼리 개선 후보 제시, 실행 전 영향 검증. AI가 제안한 SQL을 임의로 운영 DB에 자동 실행하지 않음.

## 플랫폼 범위
- 최초 완성 목표: MSSQL 버전.
- 향후 확장: PostgreSQL 등 DBMS마다 별도 Collector/Analyzer Adapter.
- 최종 사용 형태: 회원가입/로그인, 본인 DB 등록, 권한/테넌트 분리, 멀티 DB 모니터링, 알림, 대시보드, 복구 승인/감사, 배포 서비스.
- 개발 방식: 실서비스 중심 기능 구현 → 격리된 테스트 DB에서 기능 검증 → 테스트 증거 확보 → 다음 기능.

## 테스트 부하의 역할
로컬에서 여러 트랜잭션을 동시에 수행하거나 10초에 1,000~2,000건의 SQL을 실행하는 것은 **본 서비스의 모니터링·분석·진단 신뢰성을 검증하기 위한 수단**이다. 실제 사용자의 DB에는 부하 테스트를 실행하지 않는다.

## MVP v0.1.0 범위
- 포함: Spring Boot API, PostgreSQL 메타데이터, 환경변수로 등록한 MSSQL 1개 대상, 읽기 전용 DMV 조회, 5초 간격 수집, 수집 결과 저장, React 최근 60개 시점 대시보드.
- 미포함: 회원 인증/권한, 사용자의 DB 동적 등록, 암호화된 다중 DB 자격증명 보관, Deadlock 이벤트 수집, Query Store 분석, 자동복구, AI 튜닝, 알림, SaaS 멀티테넌시, 제품 운영 배포.
- 수집기 실패 시 측정값을 0으로 조작하지 않으며, 상태를 OFFLINE으로 보고. 이전 데이터는 역사 데이터로 유지.

## 구현 우선순위
A. 서비스 골격/데이터 흐름 → B. 실시간/누적 수집 정확도 향상 → C. 인증·사용자별 DB 온보딩 → D. 장애 분석 엔진 → E. 자동복구 정책 엔진 → F. 튜닝 어드바이저 → G. 부하/장애 통합 검증 → H. 공개 배포 및 강화.

최종 사용자 제공이 목표이므로 보안/인증이 갖춰지기 전에는 서비스를 인터넷에 공개하지 않는다.
